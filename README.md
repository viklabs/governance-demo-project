# Governed car ETL demo project - dev/main flow

This repository is only the sample data-engineering project. It does not contain or deploy the Streamlit Project Registry App.

It creates and refreshes:

- `it_dev.sample_project.car_makes`
- `it_dev.sample_project.car_models`
- `it_prod.sample_project.car_makes`
- `it_prod.sample_project.car_models`
- one serverless Databricks job in each workspace

The required governance tags are:

- `project_tag=<project ID generated by the v2 Registry App>`
- `environment=dev|prod`

## Branch and Bundle target names are different concepts

Register these Git branches in the v2 App:

- Development branch: `dev`
- Production branch: `main`

Register these Bundle targets:

- Bundle dev target: `dev`
- Bundle prod target: `prod`

Do not enter `prod` as the production branch unless the Git repository actually has a branch named `prod`.

## Demo flow

1. Push project changes to `dev`.
2. Workflow **01** automatically deploys the `dev` commit to `it-dev`, runs the serverless ETL job, and verifies tags.
3. Create and merge a pull request from `dev` to `main`.
4. Create a release in the Registry App for the exact full SHA on `main`.
5. Run workflow **02**. It redeploys that exact `main` SHA to `it-dev`, runs the job, verifies tags, and moves the release to `READY_FOR_APPROVAL`.
6. Approve the exact release in the Registry App.
7. Run workflow **03**. It reauthorizes the release and deploys the same SHA to `it-prod`.

The production workflow cannot pass its authorization step unless the exact release is approved in the App.
